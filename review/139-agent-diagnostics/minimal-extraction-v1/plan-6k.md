## 출력 상한 진단과 6,000-token 최소 출력 후속 계획

동결한 3,000-token 비교 16회를 완료했다. 총 12회가 모두 `finish_reason=length`로 끝났다. 풍부한 조건은 8/8이 잘렸고, 최소 조건은 상대적으로 짧은 M03·M04에서 4/4 통과했지만 M01·M02에서는 4/4가 잘렸다. strict schema 거부나 의미 판정 전 오류가 아니라 정확히 출력 상한에 도달한 결과다.

이 때문에 사전에 정한 풍부한 조건과 최소 조건의 의미 비교는 비교 가능한 기사 3건 조건을 충족할 수 없으며 점수를 내지 않는다. 3,000-token 라운드는 기술 진단으로 보존하고 개별 실패 응답을 repair하거나 재시도하지 않는다.

앞서 출력 상한이 실제 문제가 되면 1.5~2배 범위에서 조정하기로 한 방향에 따라, 별도 라운드에서 최소 출력만 6,000 tokens로 확인한다.

- 원문, 사전 gold 21개, 원문 보존 prompt, 최소 출력 schema, strict JSON Schema, 모델과 temperature는 바꾸지 않는다.
- 변경하는 값은 `max_tokens: 3000 → 6000` 하나다.
- 동일 기사 4건을 두 번씩 실행해 최대 8회다. 이 자료는 출력 상한 선택에 사용됐으므로 새 독립 평가가 아니라 개발 근거로 분류한다.
- 자동 수정·repair·실패 재시도는 하지 않는다.
- 8/8 계약 성공, 필수 사실 엄격 PASS 30/42 이상, 비지원 Claim 5% 이하, 두 반복에서 되풀이된 의미·근거·modality·귀속·분리 오류 0건일 때만 새 독립 비교로 넘길 후보로 유지한다.
- 예약 상한은 `$0.01037046`, 이번 라운드 상한은 `$0.015`, 앞선 3,000-token 실제 추정 비용을 포함한 최대 누적값은 `$0.89286156 / $1.00`이다.
- 의미 출력을 확인하기 전에 계획과 기준을 동결했으며, 인증·전송·제공자 형태·비용 불명확·원문 무결성 오류에서는 전체 실행을 중단한다.

동결 manifest SHA-256은 `9b967c78fe5292a13a4b2310ebb9623b34ed9136efb78a7de425cd5a2a5dcdde`이다. 이 후속 라운드도 제품 worker, DB 저장, 최종 #127 출력 계약과 운영 품질을 승인하지 않는다.
