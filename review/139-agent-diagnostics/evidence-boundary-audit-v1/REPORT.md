# 개별 Claim 근거 경계 무호출 감사 결과

## 1. 감사 목적과 기준선

WEB GPT 6 Pro 검토는 기사 전체 최소 추출의 기존 필수 사실 PASS가 여러 Claim의 내용과 근거를 합쳐 개별 Claim의 부족을 가렸을 수 있다고 지적했다. 이번 감사는 모델을 다시 호출하지 않고 이 교차 경계만 확인했다.

입력은 기존 4개 기사, 8개 완료 출력, 384개 Claim, 21개 필수 사실의 두 반복인 42개 판정이다. 기존 최소 추출의 `gold.json`, `review.json`, `score.json`과 `20/42`는 SHA-256으로 고정하고 수정하지 않았다. 현재 결합 구성은 이미 기각된 품질 후보이며 이번 감사로 되살리지 않는다.

## 2. 적용한 판정 경계

각 Claim에 `source_support`, `modality`, `atomicity`, `selection`과 `review_status`를 명시했다. 기존 판정 코드처럼 기록에 없는 Claim을 자동으로 `SUPPORTED`로 채우지 않으며, 원본 384개와 감사 384개의 exact key 집합이 같아야 검증을 통과한다.

Claim의 원문 지원은 해당 Claim이 실제 반환한 `source_ids`만으로 판정한다. 다른 Claim의 문장이나 근거를 빌려 주체·발언자·제품·사업부를 보충하지 않는다. 확인된 `source_document` 발행 주체는 그 회사의 생략 표현을 한정할 수 있지만, 다른 회사·인물·제품·사업부의 선행 문맥을 대신하지 않는다.

필수 사실 PASS는 모든 필수 의미를 함께 덮는 Claim 부분집합이 있고, 그 Claim들이 각자 원문 지원·modality·원자성·선정 기준을 모두 통과할 때만 허용한다. 대응 목록에 잘못된 부가 Claim이 있더라도 유효한 부분집합만으로 필수 의미가 완결되면 PASS가 가능하지만, 형제 Claim의 근거 합집합으로 개별 Claim의 부족을 메울 수는 없다.

## 3. 점수 분리

| 평가 버전 | PASS | 의미 |
| --- | ---: | --- |
| 기존 동결 평가 | 20/42 | 기존 결과이며 수정하지 않음 |
| M04-F06 gold 교정만 적용 | 22/42 | 같은 출력의 정답표 교정 효과 |
| 개별 Claim 경계, 원래 gold | 14/42 | 교정 전 새 감사 기준 |
| 개별 Claim 경계, 교정 gold | 16/42 | 이번 감사의 최종 재분류 |

기존 판정에서 6건이 PASS에서 PARTIAL로, M04-F06 두 반복은 PARTIAL에서 PASS로 바뀌었다. 따라서 최종 `16/42`는 모델 품질이 `20/42`에서 후퇴했다는 뜻이 아니라 기존 집계의 적용 단위를 바로잡고 gold 교정을 분리한 값이다.

## 4. PASS에서 PARTIAL로 바뀐 항목

| 항목 | 이유 |
| --- | --- |
| M03-F01 반복 1 | Claim 6은 삼성전자를 문장에 넣었지만 연결한 s6만으로는 소개 주체가 삼성전자임을 확인할 수 없음 |
| M03-F02 반복 1·2 | 발표 사실 Claim은 지원되지만 후속 소개 내용 Claim이 자기 근거에 발표자 선행 원문을 연결하지 않음 |
| M04-F01·F02·F03 반복 1 | 각 Claim이 제품 공개·용도와 별도의 18A 공정 속성을 한 문장에 묶어 원자성 기준을 통과하지 못함 |

M03-F02는 기존처럼 발표 Claim의 s7을 후속 내용 Claim의 s8에 합쳐 전체 사실을 PASS로 만들지 않았다. M04의 세 Claim은 다른 제품끼리만 분리하면 끝나는 것이 아니라, 실제 생성 문장 안에서 공개 행위와 별도 공정 속성을 함께 주장했는지를 확인해 판정했다.

## 5. 원본 판정을 유지하면서 정정한 항목

- M04-F06은 s20 한 단위에 와일드캣 레이크, 하이브리드 AI와 최대 17 TOPS NPU가 모두 있어 두 반복을 PASS로 교정했다. 원본 gold와 점수는 그대로 두고 `gold-amendment.json`에만 추가했다.
- M02-F04 반복 2는 삼성전자라는 상위 조직 표현만으로 메모리 사업의 의미를 넓혔다고 확정하지 않았다. 다만 s29만 연결해 메모리 사업을 확인할 근거가 없으므로 PARTIAL과 `EVIDENCE_INSUFFICIENT`는 유지했다.
- M04-F04 두 반복은 발언자의 견해를 FACT로 분류한 문제뿐 아니라, 뒤 절 Claim이 자기 근거만으로 발언자를 확인하지 못한 문제도 함께 기록했다.
- M03-F01 반복 2의 주체 누락은 modality 문제가 아니라 `REQUIRED_MEANING_OMITTED`로 정정했다.
- 조건과 대응 행동이 결속된 M02 Claim 네 개는 술어가 둘이라는 이유만으로 원자성 실패로 두지 않았다. 기존 ATOMICITY 표시 10개 중 M02 반복 1 Claim 56·61과 반복 2 Claim 53·58을 제외해 최종 원자성 FAIL은 6개다.

## 6. Claim별 결과

| 축 | 통과·포함 | 실패·제외 | 주의 |
| --- | ---: | ---: | --- |
| 원문 지원 | 291 | 93 | 연결 근거 부족과 의미 변경을 포함하므로 환각률이 아님 |
| modality·귀속 | 360 | 24 | 계획·평가의 FACT화와 발언 귀속 제거를 포함 |
| 원자성 | 378 | 6 | 조건–대응 결속은 무조건 분리하지 않음 |
| 선정 | 350 | 34 | 일반 정의 20개를 포함하며 반복 출력 수임 |
| 네 축 동시 통과 | 240 | 144 | 자동 저장 승인 수나 독립 지식 수가 아님 |

기존 대표 판정에서 지원된 것으로 보였지만 이번에 자기 근거 부족으로 확인한 Claim은 19개다. M01의 14개는 곽 사장의 발언을 직접 회사 사실로 바꾸거나 이어지는 인용 절에 발언자 원문을 연결하지 않은 경우다. M03의 5개는 삼성전자·SK하이닉스라는 다른 회사 주체를 앞선 원문에서 가져오고도 해당 ID를 연결하지 않은 경우다.

선정 제외 34개는 일반 정의 20개, 의례적 발언 2개, 중복 초과 2개, 기사 도입 요약 4개, 절 요약 1개, 겹치는 초과 Claim 1개, 주체 없는 Claim 2개와 구체 대상 없는 일반 평가 2개다. 기존 두 중복 쌍은 쌍 전체가 아니라 첫 유효 Claim 이후의 초과 Claim만 제외했다.

## 7. 반복 오류와 의미

두 반복 모두 PASS가 아닌 필수 사실은 13개다. M01의 발언 귀속·완료 상태·균형 관계 누락, M02 메모리 사업의 선행 근거, M03 발표자 근거와 협력 계획 modality, M04의 제품별 원자성·발언 근거·표 사양 근거가 반복됐다. M03-F01은 두 반복 모두 PARTIAL이지만 한쪽은 근거 부족, 다른 쪽은 Claim 주체 누락이므로 같은 원인으로 합치지 않았다.

이번 결과에서 가장 강한 병목은 최소 필드 수가 아니라 Claim이 독립적으로 필요로 하는 발언자·주체·제품 문맥을 `source_ids`에 연결하는 경계다. 다만 평탄화 과정에서 section·표 구조가 사라지는 사실이 이 오류의 원인이라는 인과관계는 아직 검증되지 않았다. 구조 손실은 직접 관측했고 유력한 가설이지만 해결책으로 확정하지 않는다.

## 8. 제품과 DB 경계

이번 감사에서 새 table, column, task kind나 publication pointer가 필요한 영속 사실은 발견하지 못했다. 실행 중 문서 구조·원문 ID·후보 대응은 runtime 정보로 두고, 일반 코드가 불변 문서의 정확한 slice·offset·인용·hash와 허용 ID를 검사한 뒤 검증된 Claim과 기존 Observation 연결만 저장하는 방향을 유지한다.

사람의 수동 판정 원장, gold, 검증 이유와 중간 후보를 제품 지식 DB에 넣지 않는다. 이번 감사가 제품 worker, 최소 출력 계약, 자동 promotion 또는 publication을 승인하지도 않는다.

## 9. 다음 한 가지 제안

다음 단계는 모델 호출이 아니라 원래 HTML에서 section·문단·목록·표의 소속과 머리글 대응을 결정적으로 보존할 수 있는지 확인하는 무호출 구조 감사다. 현재 `paragraph_id`는 DOM 평탄화 뒤 만들어져 원래 구조를 복원하지 못하므로 그대로 다시 전달하지 않는다.

구조 감사에서 원문과 위치 대응이 재현되는 정보만 확인되면, 그다음 새 기사에서 구조 정보 유무 하나만 바꾸는 비교를 별도로 계획한다. 단순 인접 ID, gold 기반 근거 주입, 자동 보충, 풍부한 출력, 별도 검증 Agent와 chunking은 이번 결과로 되살리지 않는다.

## 10. 비용·보안·변경하지 않은 범위

모델 호출은 0회이고 API 비용은 0달러다. 기존 WSL 키 파일을 읽지 않았고 키·호스트·원문·원응답을 공개하지 않았다. 제품 코드, DB, migration, SQLAlchemy metadata, fixture, 정식 문서와 의존성은 변경하지 않았다.
