# Flash·Plus 생성 비교 결과

## 1. 최종 판정

동결한 모든 후보 유지 조건을 만족한 모델은 없다. Flash는 보존율과 유효 산출량에서 앞섰지만 반복 중대 오류와 더 높은 근거 실패율 때문에 탈락했고, Plus는 낮은 필수 사실 보존율과 산출량 때문에 탈락했다.

| 항목 | Flash | Plus |
| --- | ---: | ---: |
| 호출 계약 성공 | 8/8 | 8/8 |
| 생성 Claim | 328 | 173 |
| 필수 사실 PASS | 32/48, 66.67% | 18/48, 37.50% |
| 필수 사실 PARTIAL | 14/48 | 30/48 |
| 필수 사실 FAIL | 2/48 | 0/48 |
| Claim 근거 실패 | 39/328, 11.89% | 5/173, 2.89% |
| modality·귀속 실패 | 45/328 | 64/173 |
| 원자성 실패 | 8/328 | 35/173 |
| 선정 제외 | 40/328 | 16/173 |
| 네 축 통과 유효 비중복 Claim | 217/328, 66.16% | 76/173, 43.93% |
| 호출당 유효 비중복 Claim | 27.12 | 9.50 |
| 실제 추정 비용 | `$0.00364863` | `$0.03392080` |

Flash의 필수 사실 PASS 우위는 `29.17%p`이며 C02·C03·C04에서 두 반복 모두 우세했다. 짝비교 48개는 Plus→Flash 기준으로 `PASS→PASS 18`, `PARTIAL→PASS 14`, `PARTIAL→PARTIAL 14`, `PARTIAL→FAIL 2`였다.

그러나 Flash는 NVIDIA 기사에서 뉴욕증권거래소가 계획한 협력의 행동 주체를 레드판다로 바꾼 오류를 두 반복 모두 만들었다. 이는 사람·회사·관계의 잘못된 연결을 막아야 하는 ontology-map의 중대 오류이며, 필수 사실 판정 항목 기준 `2/48`이다. Plus는 같은 사실을 온전히 보존하지 못해 PARTIAL이었지만 행동 주체를 바꾸지는 않았다.

## 2. 동결 기준 적용

| 후보 유지 기준 | Flash | Plus |
| --- | --- | --- |
| 비교 가능 기사 3개 이상 | 통과 | 통과 |
| 필수 사실 PASS 10%p 이상 우위 | 통과 | 실패 |
| 최소 2개 기사에서 두 반복 모두 개선 | 통과 | 실패 |
| 새 반복 중대 오류 없음 | **실패** | 통과 |
| Claim 근거 실패율 악화 없음 | **실패** | 통과 |
| 유효 비중복 산출량 감소 없음 | 통과 | **실패** |

Flash의 높은 Claim 수만으로 품질 우위라고 보지 않았다. 더 많은 후보는 유효 지식도 늘렸지만 근거 실패 후보와 후속 판정 비용도 함께 늘렸다. Plus의 낮은 근거 실패율 역시 어려운 사실을 충분히 남기지 않은 결과와 함께 봐야 하므로 안전한 제품 모델이라는 뜻이 아니다.

## 3. 평가 방법

출력 전에 기사마다 필수 사실 6개와 허용 modality, 충분 근거 조합과 원자성 기준을 동결했다. 호출 뒤에는 모델 이름을 숨긴 후보별로 각 Claim이 자기 `source_ids`만으로 지원되는지, modality·귀속이 맞는지, 독립 사실이 분리됐는지, POC 범위에 속하고 중복이 아닌지를 판정했다.

필수 사실 PASS는 이 네 축을 통과한 비중복 Claim 집합이 필수 의미 전체를 보존할 때만 부여했다. 다른 Claim의 근거를 빌려 개별 Claim의 부족을 메우지 않았고, 누락·PARTIAL·FAIL을 PASS로 계산하지 않았다. 판정 원장을 파일로 쓴 뒤에만 모델 매핑을 공개했다.

## 4. 해석 한계

네 공식 기사는 회사 계획·발언·복수 주체·제품 사양을 포함하도록 목적 표집했다. 통계적 대표 표본이 아니며 같은 요청을 두 번 실행한 결과를 서로 다른 기사로 세지 않는다.

평가자가 실험 설계와 호출을 함께 수행했고 모델별 Claim 수 차이를 먼저 보았으므로 엄격한 독립·이중맹검 평가가 아니다. 공개 패킷은 기사 전문과 모델 문장을 제외하므로 외부 검토자가 의미 판정을 그대로 재현할 수도 없다.

이번 결과는 모델 snapshot만 바꾼 비교다. Plus가 전반적으로 더 강하거나 Flash가 항상 더 많은 지식을 만든다는 일반 결론, prompt·입력 구조·제품 ontology 범위 중 어느 것이 최종 병목이라는 인과 결론을 내리지 않는다.

## 5. 비용·보안·계약

16회 모두 `finish_reason=stop`으로 끝났고 repair·자동 재호출은 없었다. 사전 예약은 `$0.144587`, 실제 추정 비용은 `$0.03756943`으로 `$0.30` 상한 안이다. 영구 API 키는 시험 프로세스 안에서만 읽었고 공개 자료·로그·Git에는 넣지 않았다.

원문 보존 prompt와 평가 기준은 변경하지 않았다. 이번 결과를 보고 새 예외 문구를 추가하지 않으며, 이 네 기사는 이후 독립 평가 자료로 다시 세지 않는다.

## 6. 다음 경계

현재 Flash·Plus 조합 모두 제품 생성 후보가 아니므로 #127의 출력 계약 구현이나 데모 자동 승격으로 넘어가지 않는다. 다음 작업은 새 prompt 예외가 아니라 제품 범위에 맞춘 의미 대상 출력과 검증 가능한 원문 구조 투영 중 어느 축을 먼저 비교할지 결정하는 일이다.

Agent 후보가 별도 자료에서 필수 지식 보존율 70% 이상과 중대 오류율 1% 미만을 충족하기 전에는 URL 입력·파일 업로드·SSE·저장을 구현하지 않는다. `.txt`, `.html`, `.csv`, `.xlsx`, `.docx` 지원과 `canonical_url=NULL` 계약도 이 관문 뒤의 별도 Issue로 남긴다.
