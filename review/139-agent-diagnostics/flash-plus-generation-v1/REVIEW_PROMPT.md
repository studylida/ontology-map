ontology-map Issue #139의 Flash·Plus 한국어 지식 생성 비교 결과를 독립적으로 검토해 주세요. 기준 commit과 공개 패킷의 파일을 먼저 끝까지 읽고, 코드·설정·판정 원장·집계가 서로 맞는지 확인한 뒤 판단해 주세요.

## 확인할 질문

1. 모델 조건을 공개하기 전에 동결한 Claim·필수 사실 판정과 공개 뒤 집계가 일관되는가?
2. Flash `32/48` 대 Plus `18/48`, Claim 근거 실패율 `11.89%` 대 `2.89%`, 유효 비중복 산출량 `217` 대 `76`의 분모와 해석이 타당한가?
3. Flash의 C03-F04 행동 주체 변경 두 건을 반복 중대 오류로 보고 후보를 기각한 판단이 타당한가?
4. Plus를 낮은 보존율 때문에 기각하고 어떤 모델도 승자로 고르지 않은 결론이 사전 기준과 맞는가?
5. 수동 판정에서 과도하게 PARTIAL·FAIL·선정 제외로 처리했거나 반대로 놓친 오류가 있는가? 공개 자료만으로 확인할 수 없는 것은 추정하지 말고 필요한 비공개 자료를 특정해 달라.
6. 이 결과가 prompt·입력 구조·모델 역량·제품 추출 범위 중 무엇을 직접 입증하고 무엇은 가설로만 남기는가?
7. 제품 Agent 후보를 얻기 위해 다음에 바꿀 단 하나의 축은 무엇이어야 하는가? 새 prompt 예외, 별도 검증 Agent, staging schema와 범용 orchestration을 기본 해법으로 두지 말아 달라.
8. 기존 frozen schema로 최종 Claim·Observation·Relation·attribute·event를 저장하는 경계에 새 영속 구조가 정말 필요한가?

## 반드시 구분할 것

- 호출 계약 성공과 의미 품질
- 필수 사실 보존과 생성 Claim의 지원률
- 더 많은 Claim 생성과 더 높은 유효 지식 산출량
- 반복 평가 항목과 독립 기사 수
- 모델 개선과 평가 기준 변경
- 연구 후보와 제품 자동 승격 승인

## 원하는 답변 형식

최종 판정을 `현재 결론 유지`, `일부 재판정 후 유지`, `결론 보류` 중 하나로 먼저 제시해 주세요. 그 뒤 가장 강한 찬성·반대 근거, 수치 재집계, 심각도순 평가 결함, 다음 단일 비교의 가설·변경 축·고정 조건·최대 호출·비용·성공·회귀·중단 기준, #127·#139와 기존 schema에 남길 결정 순서로 작성해 주세요.
