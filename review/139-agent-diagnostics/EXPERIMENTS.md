# 수행 과정과 결과

이 문서는 로컬의 직전 74회 시험 보고서와 마지막 49회 시험 보고서를 공개 검토용으로 정리한 것이다. 더 오래된 모든 시행착오를 복원한 연대기는 아니다. 원본 결과·정답표·점수는 별도로 보존했으며 아래 재평가를 기존 점수에 덮어쓰지 않았다.

## 1. 무엇을 해결하려 했는가

한국어 자료에서 Claim을 만들 때 주체·대상을 빠뜨리거나, 서로 다른 제품의 사실을 묶거나, 지시어만 풀고 선행 근거를 연결하지 않거나, 시점·수량·부정·계획·발언 귀속을 바꾸는 문제를 줄이려 했다. 법 제정 추진과 지원 계획은 추출에서 제외할 정보가 아니라 상태까지 보존할 정보다. 사람이 계속 판정해야 운영되는 구조를 기본 해결책으로 삼지 않는다.

여기에는 서로 다른 질문이 있다. 원문에서 필수 사실이 선정됐는지, Claim이 원문에 의해 지원되는지, 실제 연결한 근거만으로 Claim을 설명할 수 있는지, 독립 사실이 적절히 분리됐는지를 구분해야 한다. 마지막 49회는 주로 뒤의 근거 검사와 사실 분리 검사 개선이며, 추출기를 수정해 누락을 해결한 시험은 아니다.

## 2. 시험 역할과 제품 역할의 구분

| 시험 역할 | 입력과 역할 | 확인된 결과와 한계 |
| --- | --- | --- |
| Selection | 원문에서 선정한 사실과 근거를 구조화 | 기존 R6~R8 출력을 재평가함. 마지막 49회에서는 수정하지 않음 |
| Composer | 기존 선정 결과의 문장을 다시 작성 | 14회 비교에서 추가 의미·가독성 개선이 확인되지 않음. 시험 후보에서는 재작성 단계를 제외 |
| Preservation | 전체 원문과 지정 focus에서 필수 사실을 적고 Claim·근거에 대응 | 담당 오류 탐지는 했지만, 스스로 작성한 사실의 선행 근거가 빠지는 문제가 남음 |
| 복합 Fidelity | 원문 지원·선택 근거 충분성·사실 분리·인용 범위 검사 | 여러 책임이 섞인 상태에서 근거 누락과 제품 묶음을 놓침 |
| Evidence | Claim 하나와 전체 또는 실제 연결 원문의 지원 관계 검사 | 선택 근거만 제공하는 대조에서 일부 미탐 개선. 발언 귀속과 표 제한 조건 미탐 잔존 |
| Atomicity | 실제 Claim을 독립 사실로 나눌 필요가 있는지 검사 | 분해 출력으로 제품 묶음은 탐지했지만 공동 주체 누락을 분리 오류로 오판 |

제품의 본문 추출·문장 작성·제한된 판정 역할과 위 진단 역할을 일대일로 대응시키지 않는다. 진단 결과가 많다는 이유로 별도 worker·task kind·저장 table을 만드는 결정은 하지 않았다. 실제 제품 worker와 최종 저장 흐름의 구현·검증은 이번 결과에 포함되지 않는다.

## 3. 직전 74회: 평가를 바로잡고 역할을 비교

먼저 기존 R6~R8의 저장 출력 42개를 모델 호출 없이 재평가했다. 표현 형식과 의미 보존을 혼동한 평가, 공동 행위에서 한 참여자가 참여했다는 약한 명제와 단독 행위 명제의 차이를 정리했다. 자연 기사에서 주체가 모호했던 A4는 `UNRESOLVED`로 남겼으며 통과로 바꾸지 않았다. 뒤의 A4 통제 시험은 주체를 명시한 합성 자료다.

| 저장 출력에 적용한 기준 | R6 | R7 | R8 |
| --- | ---: | ---: | ---: |
| 기존 5개 의미·품질 축 전체 통과 | 7/14 | 8/14 | 4/14 |
| 재평가 5개 축 전체 통과 | 8/14 | 9/14 | 6/14 |
| 재평가 출력 소비 계약까지 통과 | 5/14 | 6/14 | 4/14 |

이 변화는 기준과 해석 변경의 효과이며 모델 개선이 아니다. 예를 들어 PLAN 값이 별도 필드에 있더라도 화면에서 사용할 Claim 문장이 계획을 현재 사실로 읽히게 만들면 소비 계약 실패를 유지했다.

74회는 Composer 14회, Preservation 최초 14회와 수정 14회, Fidelity 최초 14회와 수정 14회, 표 Selection 대조 4회로 구성된다. 7개 개발 지점의 정상·오류 대조쌍이지 독립 기사 14편이 아니다. 검증 모델에는 정답표·정상/오류 표시는 주지 않았지만 focus 자체는 시험자가 지정했다.

- Composer는 26문장 중 23문장을 그대로 반환했다. 의미 개선·새 의미 오류·가독성 개선은 각각 0건이다. 기존 계획 명시 누락 3문장과 거주 의향의 의미 변경 1문장을 복구하지 못했고 조사 삭제 1건에는 작은 가독성 회귀가 있었다. 별도 재작성이 이 표본에서 도움이 없었다는 결과이지 제품 역할을 영구 삭제한 결정이 아니다.
- Preservation은 담당 오류 5/5를 두 버전 모두 탐지했다. 오류 유무 일치는 13/14, 세부 판정은 12/14로 같았다. 작성한 사실의 근거 충분성은 묶음 기준 8/14에서 12/14, 사실 기준 14/26에서 24/26으로 개선됐다. A5의 두 사실에는 선행 s18이 계속 빠졌다.
- Fidelity는 담당 오류 3/5를 두 버전 모두 탐지했다. 오류 유무 일치는 11/14로 같았고 네 검사 모두 일치는 10/14에서 11/14로 변했다. 근거 누락·제품 묶음의 미탐과 약한 참여 명제에 대한 오탐이 남았다.
- 표 Selection의 원형 입력·셀 구조 입력 대조는 4회 모두 통과했다. 이 작은 비교에서 구조 보조의 추가 이익은 확인되지 않았다. 이후 Evidence의 표 제한 조건 오류까지 해결했다는 증거로 사용할 수 없다.

위 Preservation 수치는 당시 평가 버전이다. 이후 사용자가 A3의 기술 적용 대상·평가 표현도 실제 발언자에게 귀속해 보존하도록 명확히 했다. 과거 정상 후보의 그 부분 누락을 경고한 두 출력은 새 기준에서 타당한 경고로 재분류했다. 과거 점수는 보존했고 이를 검증 모델의 개선으로 계산하지 않았다.

## 4. 마지막 49회: 입력 범위와 출력 방식을 분리 비교

### 고정 조건

마지막 49회는 싱가포르 Model Studio의 `qwen3.7-plus-2026-05-26`, temperature 0, thinking false, stream false, 최대 출력 2200 token으로 수행했다. JSON Object 응답과 로컬 Pydantic 검증을 사용했으며 provider의 strict JSON Schema 준수를 검증한 시험은 아니다. Flash `qwen3.7-flash-2026-07-15`는 직전 Composer·Selection 비교에 사용했다. 모델 ID·설정·비용은 당시 기록이며 현재 제공 여부나 청구 가격을 보증하지 않는다.

새 A3 정상 후보는 기술 적용 대상·평가·발언 귀속을 담고, 오류 후보는 평가·계획을 유지하되 귀속을 제거했다. 이 두 후보는 이전과 동일 입력의 회귀 비교에서 제외했다. 나머지 6축은 이전 기대값을 유지했다.

### Evidence

첫 pilot은 같은 prompt·schema·모델·설정에서 전체 기사 또는 실제 연결 원문만 주는 조건을 비교했다. 한 요청에는 Claim 하나만 넣었다. 선택 원문 조건에는 다른 Claim·미선택 원문·평가 metadata가 없고, 누락된 선행 근거를 코드가 보충하지 않았다.

| 단계 | 호출 수 | 판정 일치 | 판정·이유·근거 모두 일치 |
| --- | ---: | ---: | ---: |
| 최초 전체 기사 A1·A5 | 6 | 4/6 | 2/6 |
| 최초 연결 원문 A1·A5 | 6 | 6/6 | 1/6 |
| prompt만 수정한 연결 원문 A1·A5 | 6 | 6/6 | 6/6 |
| 수정판을 나머지 5축으로 확대 | 19 | 17/19 | 16/19 |
| 최종 수정판의 고유 Claim 합계 | 25 | 23/25 | 22/25 |

전체 기사 조건은 A5의 잘못 연결된 근거 두 건을 모두 놓쳤고, 선택 원문 조건은 두 건을 모두 잡았다. 그러나 최초 선택 원문 조건도 FAIL 3건에 실제 검사한 ID를 쓰지 않았고 정상 A5의 판단 근거에서 선행 s18을 빠뜨렸다. 이 문제는 올바른 FAIL을 또 하나의 의미 오답으로 센 것이 아니라 근거 기록 결함으로 구분했다.

한 차례 수정에서는 PASS에 필요한 선행·머리글 ID와 FAIL에서 실제 검사한 ID를 반환하도록 prompt만 명확히 했다. pilot은 통과했으나 확대 단계에서 A3 발언자의 평가 객관화, A7 제품 간 제한 조건 이동을 놓쳤다. A2에서는 상태 불일치를 잡았지만 실제 Claim과 다른 단어를 이유에서 인용하고 완료 상태도 덧붙였다.

최종 25개 중 실제 근거 오류 7개는 5개만 탐지했고, 정상 18개는 모두 통과했다. 전체 23/25만 보고 오류 탐지 능력이 충분하다고 해석하면 안 된다. 이유·근거까지 포함한 엄격한 수치는 22/25다. 같은 Claim·선택 근거 23개만 이전 수정 Fidelity와 비교하면 20/23에서 22/23으로 변했다. A4 한 건과 A5 두 건이 개선되고 A7 한 건이 회귀했다. 여러 설정과 책임이 함께 달라졌으므로 이 종합 비교로 특정 변경 하나의 인과 효과를 확정하지 않는다.

### Atomicity

원문과 Claim 묶음을 그대로 두고 판정만 반환하는 조건과 독립 사실 목록도 출력하는 조건을 비교했다. 사실 목록은 실제 입력 문장을 분해하는 시험 결과이며 빠진 의미를 자동 복구하거나 DB에 저장할 Claim을 만드는 것이 아니다.

| 단계 | 요청 묶음 | 묶음 판정 일치 | Claim 판정 일치 |
| --- | ---: | ---: | ---: |
| 판정만 | 4 | 2/4 | 5/7 |
| 독립 사실 목록 추가 | 4 | 3/4 | 6/7 |
| 목록 조건의 prompt 한 차례 수정 | 4 | 3/4 | 6/7 |

목록 출력은 A6의 제품별 독립 사양 묶음을 탐지하고 내용을 보존해 분리했다. 반면 A4의 한 참여자만 적은 Claim을 단독 행위로 해석하고 분리 FAIL을 반환했다. 실제 분해 목록은 하나이고 중복도 없었다. 공동 주체 보존 결함을 Atomicity가 대신 판정하는 오탐은 한 차례 수정 후에도 남았다.

## 5. 완료·중단·보류를 구분

| 작업 | 현재 상태 | 이유 |
| --- | --- | --- |
| 평가 기준 분리와 원본 보존 | 완료 | 과거 점수·gold·요청·출력을 덮어쓰지 않음 |
| Evidence 입력 범위 12회, Atomicity 출력 비교 8회 | 완료 | 부분 개선과 결함을 각각 관측 |
| 역할별 한 차례 prompt 수정 10회 | 완료 | 원래 버전 보존. Atomicity 오탐 잔존 |
| Evidence 확대 19회 | 완료, 실패 발견 | 미탐 2건·이유 오류 1건 |
| Evidence 전체 반복 25회 | 중단 | 확대 후 남은 오류로 합의한 진행 조건 미충족 |
| Atomicity 확대 10회·반복 14회 | 중단 | 수정 pilot에서 같은 오탐이 남음 |
| Preservation가 적은 사실의 추가 근거 검사 | 보류 | 선행 조건인 근거 검사 후보가 통과하지 못함. 26개 사실에 대응하는 15개 고유 요청의 기대값만 사전 검토 |
| 새 긴 기사 독립 평가 | 기존 보류 유지 | 자료를 조정용으로 열지 않음. 이번 부분 개선으로 재개하지 않음 |
| 자동 수정·제품 worker·새 schema·운영 파이프라인 | 실행 제외 유지 | 이번 진단 시험의 승인 범위 밖 |

Preservation 추가 근거 검사의 사전 기대값은 15개 고유 요청 중 14 PASS·1 FAIL이다. 같은 요청에 대응하는 기존 A5 사실 두 건에는 s18이 빠져 있다. 이 기대값은 실행 결과가 아니며 26개 사실을 독립 호출 26개처럼 세지 않는다.

전체 재실행을 멈춘 이유는 예산 부족이 아니라 한 차례 근거 있는 수정 후에도 실패하면 멈추기로 한 진행 조건이다. 이 조건이 독립 평가를 지나치게 늦추는지 자체는 후속 검토 질문으로 열어 두지만, 검토 요청만으로 보류 시험을 재개하지 않는다.
